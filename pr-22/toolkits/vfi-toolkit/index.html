VFI Toolkit

A MATLAB toolkit for solving macroeconomic models by value function iteration. You write the model's return function and grids; the toolkit solves the dynamic programming problem on the GPU, computes the agent distribution, evaluates the statistics you ask for, and finds the general equilibrium and the transition path. Its home ground is heterogeneous-agent, life-cycle and overlapping-generations models.

vfitoolkit.com ↗ Start with the life-cycle introduction ↗

Written and maintained by Robert Kirkby. Open source under the GPL-3.0 since 2015, with its code, examples and replications on GitHub and a forum for questions.

01

Introduction

VFI Toolkit takes one approach and makes it fast, general and hard to get wrong: discretise the state space, iterate the Bellman equation, and let the GPU do the work. The result is a toolkit in which the model is a short script and the numerics are somebody else's problem.

You describe the model

A model is a return function, written in MATLAB with the arguments in a fixed order (the decision, next period's endogenous state, this period's state, the shocks, then parameters), together with grids for each state and a transition matrix for each shock. Parameters live in a struct and are passed by name, so the same code solves a calibration or a whole grid of them. Age-dependent parameters, grids and shocks are given once and indexed by age.

The toolkit solves it

One call solves the value function and policy for an infinite-horizon or a finite-horizon problem. Further calls compute the stationary or age-conditional distribution of agents, evaluate any function of the state on that distribution (means, quantiles, Lorenz curves, life-cycle profiles, panel simulations), close the general equilibrium, and solve the transition path between two equilibria. Everything runs on the GPU without the user writing a line of GPU code.

The design bet

Pure discretisation, then speed-ups where they are safe

Choices are made on grids, so the solver never interpolates a value function or searches a continuous space, and the accuracy of a solution is a question of grid size that the user can check. Speed comes from the GPU, from Howards improvement and relative VFI in infinite horizon, and from two optional layers the toolkit adds when the model allows them: a grid interpolation layer that refines the choice of next period's asset between grid points, and divide-and-conquer, which exploits monotone policies.

Who it is for

Researchers and students who want the model, not the solver

The toolkit grew out of teaching and replication. Its introductions build a life-cycle model and an OLG model up feature by feature, each step a runnable script, and its replication repository reproduces the tables and figures of published papers with notes on where they differ. Users need MATLAB and, for anything beyond illustrations, an NVIDIA GPU.

Julia next. The project is developing a Julia version of the toolkit. It will run models without a MATLAB licence, in Jupyter notebooks as well as scripts, which brings the toolkit's solutions into the same executable form as the library's Python and Julia ones. This page will link it when the project announces it.

02

Models it solves

Any model that can be written as a dynamic programming problem over a discretised state space, with one or more agents whose decisions aggregate to prices. In practice, the toolkit's examples and replications cluster in these families.

Infinite horizon

Heterogeneous-agent incomplete markets

Aiyagari and Huggett economies: the stationary equilibrium, the wealth distribution and the transition path after a change in policy or technology. Guerrieri–Lorenzoni's credit crunch is a worked example.

Examples ↗ Finite horizon

Life-cycle models

Households that age, work, retire and die, with age-dependent income risk, permanent types, bequests, endogenous labour, housing-style assets and portfolio choice over a risky asset. The toolkit's introduction builds one up over eighteen models.

Intro to Life-Cycle Models ↗ Finite horizon · general equilibrium

Overlapping generations

Life-cycle households closed in general equilibrium, with taxes, pensions and government budgets, demographics, and the transition path between steady states. Auerbach–Kotlikoff, Conesa–Krueger and Huggett (1996) are among the replications.

Intro to OLG Models ↗ Firm dynamics

Firm entry and exit

Hopenhayn's industry equilibrium, Hopenhayn–Rogerson's labour-market frictions and Restuccia–Rogerson's misallocation, with endogenous exit decisions and a distribution of firms.

Examples ↗ Representative agent

Growth and business cycles

The stochastic neoclassical growth model and a basic real business cycle model, used as the first tutorials: a small problem on which to learn the toolkit's conventions before adding heterogeneity.

Examples ↗ Replications

Twenty-six published papers

From Imrohoroglu (1989) and Huggett (1993) to Guvenen (2007), Kitao (2008) and Guerrieri–Lorenzoni (2017). Each folder reproduces every model-based table and figure and comes with a PDF that sets the originals beside the replication.

03

Capabilities

What the solvers can represent, as the toolkit's documentation names it. Each item is an option on the same few commands rather than a separate solver, so features combine.

Shocks
  • Markov shocks
  • i.i.d. shocks
  • Semi-exogenous shocks that depend on a decision
  • Between-period shocks
  • Age-dependent grids and transitions
  • Correlated shocks and VARs
Discretisation
  • Tauchen
  • Tauchen–Hussey
  • Rouwenhorst
  • Farmer–Toda
  • Gaussian-mixture and stochastic-volatility innovations
  • Life-cycle AR(1) and VAR(1) processes
Preferences
  • Time-separable
  • Epstein–Zin
  • Quasi-hyperbolic, naive or sophisticated
  • Gul–Pesendorfer temptation
  • Ambiguity aversion
  • State-dependent discounting
  • Warm-glow bequests
States and assets
  • Several endogenous states
  • Risky asset and portfolio choice
  • Experience assets
  • Residual assets
  • Permanent types
  • Endogenous exit
Solution
  • Pure discretisation with refinement
  • Grid interpolation layer
  • Divide-and-conquer
  • Howards improvement and policy iteration
  • Relative VFI
  • Low-memory modes
Equilibrium and output
  • Stationary and age-conditional distributions
  • Statistics of any function on the distribution
  • Life-cycle profiles
  • Panel simulation
  • General equilibrium
  • Transition paths
  • Method-of-moments estimation

The toolkit's own reference documentation lists every option with its default. CPU mode supports only the basic problem and is meant for illustration; for research use, the project recommends a GPU.

04

Learn it

The project teaches by example. Each route below is a sequence of runnable scripts, with the economics explained alongside the code.

01

An Introduction to Life-Cycle Models

Eighteen models, starting from a household that only chooses consumption and adding one feature at a time, with assignments. The project's recommended starting point.

 02

An Introduction to OLG Models

Builds up from a simple overlapping-generations economy to general equilibrium with taxes, pensions and firms, and on to transition paths.

 03

Examples

Short scripts for the growth model, the RBC model, Epstein–Zin preferences, Aiyagari with its transition path, and firm entry and exit.

 04

Replications

Twenty-six papers reproduced end to end, each with a PDF comparing the original and replicated results and noting any differences.
Workshop

The 2025 workshop teaches the toolkit in recorded sessions, starting from basic life-cycle models; its materials are on GitHub and the project recommends it as an alternative to the written introduction.

Reference

The command reference in the repository documents each solver's inputs and options; the pseudocodes explain what the main commands do, and the docs repository covers exotic preferences and entry and exit in depth.

The paper

Kirkby, R. (2017). A Toolkit for Value Function Iteration. Computational Economics, 49(1), 1–15. doi:10.1007/s10614-015-9544-1. Cite it when you use the toolkit.

Getting the code

Clone or download the repository and add it to the MATLAB path. The project keeps installation and setup notes on its website.

In the library

Where VFI Toolkit meets the library's baseline set. The project chooses which models to solve and submits each solution in its own notation; this is the library's reading of the fit, from the toolkit's documentation and examples, not a commitment by the project.

Buffer-stock saving

Consumption–saving under income risk · description v0.1

A one-asset, two-shock problem the infinite-horizon solver is built for. The library's buffer-stock slots are open.

Slot open

Aiyagari · Krusell–Smith

Incomplete-markets heterogeneous agents · description planned

Aiyagari (1994) is solved in the toolkit's examples and replications, with its transition path. Krusell–Smith's aggregate shocks are handled by the toolkit's recursive-equilibrium routines.

Example exists

A two-asset HANK model

Heterogeneous-agent New Keynesian · description planned

Two endogenous assets fit the solvers, and transition paths are a core feature. A HANK model would be new ground for the toolkit's examples.

Within reach

A small New Keynesian DSGE model

Representative-agent DSGE · description planned

Representative-agent models solved by perturbation are not what the toolkit is for, although its growth and RBC examples show the global approach on small problems.

Not its focus

A baseline agent-based macro model

Macro from interacting heterogeneous agents · description planned

Agent-based simulation is outside the dynamic programming framework the toolkit provides.

Not its focus

A filled slot in the library table links the toolkit's solution, names its submitter and shows the description version it follows. Solutions from the MATLAB toolkit are scripts that need a GPU, so the library accepts them with the author's results and executed outputs rather than re-running them in CI; the contributing guide explains what to include. The Julia version, once released, will let solutions be submitted as notebooks that the library can run.
